### Does NATS from Rails Keep Up at 1M Users?

**Short answer: Yes — Rails is NOT the bottleneck.**

Here is why:

Rails publishes to NATS once per broadcast event.
```
Rails.broadcast("chat_room_42", data)
  → nats.publish("TURBOCABLE.chat_room_42", msgpack_bytes)
  → NATS persists it
  → NATS pushes to gateway consumer
  → Gateway fans out to ALL subscribers of that stream
```

Rails never touches WebSocket connections. It never knows how many
users are connected. It fires one NATS publish and moves on.
The 1M connection fan-out is entirely inside the Rust gateway.

**What is the actual throughput of nats-pure from Ruby?**

- NATS publish from Ruby (nats-pure gem) is a simple TCP write
- Benchmarks: ~50k–100k publishes/sec from a single Ruby process
- A typical Rails app does far fewer than 1k broadcasts/sec
- There is zero fan-out logic in Rails

**The bottleneck you must design for is:**

```
Gateway fan-out:
  1 broadcast → fan out to N connections
  N = up to 1,000,000 (worst case: global broadcast)

This is a Rust problem, not a Ruby problem.
```

The only NATS concern on the Rails side is connection pooling —
use a single persistent NATS connection per Rails process
(nats-pure handles reconnect automatically).

# OS and Infrastructure Tuning for 1M WebSocket Connections

**Read this before writing a single line of gateway code.**
These are not optional. Without them, Linux will stop you at ~65k connections
regardless of how good your Rust code is.

---

## 1. Why the OS is the First Bottleneck

Each WebSocket connection is a TCP socket, which is a file descriptor.
Linux defaults:
- Per-process fd limit: **1024**
- System-wide fd limit: **~800k** (varies by distro)
- Ephemeral port range: **28,232 ports** (blocks outbound, not inbound)
- TCP backlog: **128**

For 1M inbound connections you need to raise all of these.

---

## 2. Kernel Parameters (`/etc/sysctl.conf`)

Apply on every gateway node. Commit this file to `infra/sysctl_gateway.conf`:

```bash
# Maximum file descriptors system-wide
fs.file-max = 12000000

# Per-process limits (also set in systemd unit / ulimit)
fs.nr_open = 4000000

# TCP buffer sizes
# min / default / max (bytes)
net.core.rmem_max          = 16777216
net.core.wmem_max          = 16777216
net.ipv4.tcp_rmem          = 4096 87380 16777216
net.ipv4.tcp_wmem          = 4096 65536 16777216

# Backlog — number of connections waiting to be accepted
net.core.somaxconn         = 65535
net.ipv4.tcp_max_syn_backlog = 65535

# TIME_WAIT recycling — lets sockets be reused faster
net.ipv4.tcp_tw_reuse      = 1
net.ipv4.tcp_fin_timeout   = 15

# Increase ephemeral port range (needed if gateway makes outbound connections)
net.ipv4.ip_local_port_range = 1024 65535

# Increase max connections tracked
net.netfilter.nf_conntrack_max = 2000000  # only if using iptables/nftables
net.core.netdev_max_backlog    = 65536

# Disable TCP slow start after idle (better for WebSocket keep-alives)
net.ipv4.tcp_slow_start_after_idle = 0
```

Apply immediately (and on reboot):
```bash
sysctl -p /etc/sysctl.conf
```

## 4. TCP Stack for WebSockets at Scale

WebSocket connections are long-lived. The default TCP keepalive (2 hours)
means dead connections linger for 2 hours before the OS reclaims them.
Tune for faster dead connection detection:

```bash
# In sysctl.conf — detect dead connections in ~3 minutes
net.ipv4.tcp_keepalive_time     = 60   # start probing after 60s idle
net.ipv4.tcp_keepalive_intvl    = 10   # probe every 10s
net.ipv4.tcp_keepalive_probes   = 6    # 6 failed probes → close
```

The Rust gateway also sends its own application-level ping every 30s
(configurable). This is faster than relying on TCP keepalive.

---

## 5. Memory Estimation for 1M Connections

Before writing code, understand the memory budget:

| Allocation | Per connection | 1M total |
|------------|---------------|----------|
| TCP socket (kernel) | ~3–4 KB | ~3.5 GB |
| tokio task (gateway) | ~1–2 KB | ~1.5 GB |
| Connection struct (Rust) | ~256 bytes | ~256 MB |
| mpsc channel (512 capacity) | ~16 KB | ~16 GB ← **problem** |
| mpsc channel (64 capacity) | ~2 KB | ~2 GB |
| mpsc channel (16 capacity) | ~512 bytes | ~512 MB |

**Key insight:** The outbound mpsc channel capacity is the dominant memory cost.
Set it to 16–32 for typical chat apps. Only increase if your use case
requires bursty fan-out with slow consumers.

**Total realistic budget at 1M connections: 8–12 GB RAM per gateway node.**
Plan for 3 gateway nodes with 32 GB RAM each.

---

## 6. Network Interface

For a single gateway node serving 1M connections:
- Network card: at least 10 GbE (25 GbE recommended)
- IRQ affinity: pin NIC interrupts to specific CPU cores
- RSS (Receive Side Scaling): enable multi-queue on the NIC

```bash
# Check NIC queue count
ethtool -l eth0

# Set number of queues to match CPU count
ethtool -L eth0 combined $(nproc)

# Pin NIC IRQs to cores 0-7 (adapt to your NIC)
for i in $(cat /proc/interrupts | grep eth0 | awk '{print $1}' | tr -d ':'); do
  echo 1 > /proc/irq/$i/smp_affinity
done
```

# TurboCable — System Architecture

## 1. The Right Mental Model

```
Rails app          → publishes events (1 event per broadcast)
NATS JetStream     → persists and routes events (the bus)
Rust gateway       → holds all 1M WebSocket connections
                     fans out 1 event to N subscribers
JS client          → reconnects, replays, calls received(data)
```

Rails has NO knowledge of WebSocket connections.
The gateway has NO knowledge of your business logic.
They communicate only through NATS subjects.

## 3. Connection Capacity Planning

```
Target: 1,000,000 concurrent WebSocket connections

3 gateway nodes × 333k each = 1M

Per-node requirements:
  RAM:   32 GB
  CPU:   16 vCPU  (Tokio multi-thread runtime)
  Net:   10 GbE
  OS:    LimitNOFILE=2000000 in systemd unit

NATS cluster:
  3 nodes (fault tolerance — survive 1 node failure)
  RAM: 8 GB each
  Storage: SSD, min 100 GB each

Rails:
  Existing cluster — no changes needed
  NATS publish is one TCP write per broadcast
```

---

## 4. Broadcast Fan-Out at Scale

The worst case is a global broadcast to all 1M connections.
The gateway must complete the fan-out in under 50ms.

```
1 NATS message arrives at gateway
  │
  ▼
FanoutEngine::fanout("global", frame)
  │
  ├── DashMap lookup: "global" → [conn_1, conn_2, ... conn_333_000]
  │   (shard lock held for microseconds, then released)
  │
  ├── SmallVec clone of conn_id list  (stack-allocated for small lists)
  │
  └── for each conn_id:
        tx.try_send(frame.clone())   ← Bytes::clone() = 1 atomic refcount++
        if tx is full → log + skip   ← never block, never allocate

At 333k connections:
  333k × Bytes::clone() = 333k atomic increments
  In Rust on 16 cores = ~5–10ms fan-out time

At 1M connections (full cluster, 3 nodes):
  Each node fans out to its own ~333k connections in parallel
  Total wall time ≈ same 5–10ms
```

# Coding Standards

## Rust

### Performance Rules — Non-Negotiable From Day 1

**1. Use jemalloc as the global allocator.**
The default system allocator fragments badly under millions of small
allocations. jemalloc is designed for long-running servers.
```toml
# Cargo.toml
jemallocator = "0.5"
```
```rust
// src/main.rs — must be the FIRST thing in the file
#[global_allocator]
static ALLOC: jemallocator::Jemalloc = jemallocator::Jemalloc;
```

**2. `bytes::Bytes` for ALL frames in fan-out paths.**
`Bytes::clone()` = one atomic increment. Zero copy. Zero allocation.
Never use `Vec<u8>` in anything that touches the fan-out hot path.

**3. `DashMap` everywhere shared state is accessed concurrently.**
`Mutex<HashMap>` is a single global lock — it will serialize your
16-core CPU into a single thread under load.
DashMap shards internally (default 16 shards) so most operations
never contend.

**4. Bounded channels with hard backpressure.**
```rust
let (tx, rx) = tokio::sync::mpsc::channel::<Bytes>(16);
// 16 capacity × ~512 bytes = 8 KB per connection
// At 1M connections = 8 GB RAM for channels
// Channel full → log once → disconnect slow client
// Never use unbounded_channel() — it will OOM at scale
```

**5. No allocations in the fan-out hot path.**
Inside `FanoutEngine::fanout()`: no `format!`, no `String::new()`,
no `Vec::push()` without pre-allocated capacity, no `.to_string()`.

**6. `SO_REUSEPORT` — multiple listener threads.**
```rust
// Each Tokio worker thread gets its own accept loop
// The kernel distributes new connections across threads
// No single accept() call is a bottleneck
let listener = TcpListener::bind("0.0.0.0:9292")?;
listener.set_reuseport(true)?;
```

**7. Clippy from day 1 as compiler errors.**
```toml
# gateway/.cargo/config.toml
[build]
rustflags = ["-D", "warnings"]
```

## main.rs — Full Startup

```rust
// src/main.rs

// MUST be first — sets global allocator to jemalloc
// This alone improves throughput ~15-20% under sustained load
#[global_allocator]
static ALLOC: jemallocator::Jemalloc = jemallocator::Jemalloc;

use std::sync::Arc;
use clap::Parser;

mod auth;
mod config;
mod connection;
mod fanout;
mod metrics;
mod protocol;
mod pubsub;
mod server;

#[tokio::main(flavor = "multi_thread")]
async fn main() {
    // JSON structured logging in production
    // RUST_LOG=turbocable_gateway=info,async_nats=warn
    tracing_subscriber::fmt()
        .with_env_filter(tracing_subscriber::EnvFilter::from_default_env())
        .json()
        .init();

    let cfg = config::Config::parse();

    // Raise fd limit in-process as a safety net
    // systemd LimitNOFILE is the real fix — this is defensive
    raise_fd_limit(2_000_000);

    let metrics  = Arc::new(metrics::Metrics::new());
    let registry = Arc::new(connection::registry::Registry::new());
    let keys     = auth::key_watcher::KeyStore::watch_nats(&cfg.nats_url).await
                     .expect("Failed to connect to NATS for key watching");

    // Start NATS push consumer in background
    let reg_clone = registry.clone();
    tokio::spawn(async move {
        pubsub::nats::start(&cfg.nats_url, reg_clone, &cfg.node_id)
            .await
            .expect("NATS consumer failed");
    });

    tracing::info!(port = cfg.port, node_id = %cfg.node_id, "TurboCable gateway starting");

    server::run(cfg, registry, keys, metrics).await;
}

fn raise_fd_limit(target: u64) {
    use std::os::unix::process::CommandExt;
    let (soft, hard) = rlimit::Resource::NOFILE.get().unwrap_or((1024, 1024));
    if soft < target {
        let new = target.min(hard);
        if let Err(e) = rlimit::Resource::NOFILE.set(new, hard) {
            tracing::warn!("Could not raise fd limit to {new}: {e}. Set LimitNOFILE in systemd.");
        } else {
            tracing::info!("Raised fd limit to {new}");
        }
    }
}
```

```rust
/// The central registry.

///
/// DashMap uses 64 shards by default.
/// At 1M connections, each shard holds ~15k entries.
/// Most operations touch only 1 shard → near-zero contention.
pub struct Registry {
    /// conn_id → outbound channel
    /// conn_id is a u64 (not String) to avoid heap allocation per connection
    senders: DashMap<u64, Sender<Bytes>>,

    /// stream_name → list of conn_ids
    /// SmallVec<[u64; 32]>: stores up to 32 conn_ids on the stack
    /// Streams with few subscribers (common) never touch the heap
    streams: DashMap<String, SmallVec<[u64; 32]>>,

    /// Monotonic counter for generating conn_ids
    next_id: AtomicU64,

    /// Active connection count (for metrics)
    active: AtomicU64,
}

impl Registry {
    pub fn new() -> Self {
        Self {
            // 64 shards: at 1M entries, each shard holds ~15k items
            // Increase to 128 if you see contention in profiling
            senders:  DashMap::with_capacity_and_shard_amount(1_100_000, 64),
            streams:  DashMap::with_capacity(4096),
            next_id:  AtomicU64::new(1),
            active:   AtomicU64::new(0),
        }
    }

    pub fn allocate_id(&self) -> u64 {
        self.next_id.fetch_add(1, Ordering::Relaxed)
    }

    pub fn register(&self, conn_id: u64, tx: Sender<Bytes>) {
        self.senders.insert(conn_id, tx);
        self.active.fetch_add(1, Ordering::Relaxed);
    }

    pub fn deregister(&self, conn_id: u64) {
        self.senders.remove(&conn_id);
        self.active.fetch_sub(1, Ordering::Relaxed);
        // Note: stream subscription cleanup is done by the connection handler
        // before calling deregister, to avoid scanning all streams here
    }

    pub fn subscribe(&self, conn_id: u64, stream: &str) {
        self.streams
            .entry(stream.to_owned())
            .or_default()
            .push(conn_id);
    }

    pub fn unsubscribe(&self, conn_id: u64, stream: &str) {
        if let Some(mut conns) = self.streams.get_mut(stream) {
            conns.retain(|&id| id != conn_id);
        }
    }

    /// Hot path — called for every inbound NATS message.
    /// Must not allocate. Must not block.
    #[inline(always)]
    pub async fn fanout(&self, stream: &str, frame: Bytes) {
        let Some(conns) = self.streams.get(stream) else { return };

        // Clone the subscriber list while holding shard lock
        // SmallVec::clone for ≤32 items = memcpy on the stack = ~ns
        let targets: SmallVec<[u64; 32]> = conns.clone();
        drop(conns); // ← release DashMap shard lock immediately

        for &conn_id in &targets {
            if let Some(tx) = self.senders.get(&conn_id) {
                // try_send never blocks — if channel is full, drop the frame
                // for this connection and log it. Never slow down other conns.
                if tx.try_send(frame.clone()).is_err() {
                    // frame.clone() = one atomic refcount increment (~1ns)
                    tracing::warn!(conn_id, "slow client — frame dropped");
                }
            }
        }
    }

    pub fn connection_count(&self) -> u64 {
        self.active.load(Ordering::Relaxed)
    }
}
```

## Connection Handler — Per-Connection Lifecycle

```rust
// src/connection/handler.rs
use axum::extract::ws::{Message, WebSocket};
use bytes::Bytes;
use std::sync::Arc;
use tokio::sync::mpsc;

use crate::{
    auth::jwt::{AuthContext, JwtVerifier},
    connection::registry::Registry,
    metrics::Metrics,
    protocol,
};

pub async fn handle(
    socket:   WebSocket,
    token:    String,
    verifier: Arc<JwtVerifier>,
    registry: Arc<Registry>,
    metrics:  Arc<Metrics>,
) {
    // 1. Verify JWT before doing anything
    let claims = match verifier.verify(&token) {
        Ok(c)  => c,
        Err(e) => {
            tracing::warn!("Auth rejected: {e}");
            metrics.auth_rejected.inc();
            return;  // close connection
        }
    };

    let conn_id = registry.allocate_id();
    // Bounded channel — 16 frames backpressure
    // At 1M connections: 16 × 64 bytes avg = 1 KB per conn = 1 GB total
    let (tx, mut rx) = mpsc::channel::<Bytes>(16);

    registry.register(conn_id, tx);
    metrics.connections_active.inc();
    metrics.connections_total.inc();

    tracing::debug!(conn_id, user = %claims.sub, "connection established");

    let (mut ws_sender, mut ws_receiver) = socket.split();

    // Outbound task: drain the mpsc channel → write to WebSocket
    // Runs independently — a slow WebSocket write doesn't block other connections
    let send_task = tokio::spawn(async move {
        while let Some(frame) = rx.recv().await {
            if ws_sender
                .send(Message::Binary(frame.to_vec()))
                .await
                .is_err()
            {
                break;
            }
        }
    });

    // Track which streams this connection has subscribed to
    // Used for cleanup on disconnect
    let mut subscribed_streams: SmallVec<[String; 8]> = SmallVec::new();

    // Inbound loop: read WebSocket → dispatch commands
    while let Some(Ok(msg)) = ws_receiver.next().await {
        match msg {
            Message::Text(txt) => {
                if let Err(e) = protocol::json::handle_command(
                    &txt, conn_id, &claims, &registry, &mut subscribed_streams,
                ).await {
                    tracing::debug!(conn_id, "command error: {e}");
                }
            }
            Message::Binary(bin) => {
                if let Err(e) = protocol::msgpack::handle_command(
                    &bin, conn_id, &claims, &registry, &mut subscribed_streams,
                ).await {
                    tracing::debug!(conn_id, "msgpack command error: {e}");
                }
            }
            Message::Close(_) => break,
            Message::Ping(_)  => {} // axum handles pong automatically
            _                 => {}
        }
    }

    // Cleanup — must happen before deregister
    for stream in &subscribed_streams {
        registry.unsubscribe(conn_id, stream);
    }
    registry.deregister(conn_id);
    metrics.connections_active.dec();
    send_task.abort();

    tracing::debug!(conn_id, "connection closed");
}
```

```rust
// src/server.rs
use socket2::{Domain, Protocol, Socket, Type};
use std::net::SocketAddr;

pub async fn run(cfg: Config, registry: Arc<Registry>, keys: Arc<KeyStore>, metrics: Arc<Metrics>) {
    let app = axum::Router::new()
        .route("/cable",   axum::routing::get(ws_handler))
        .route("/health",  axum::routing::get(health_handler))
        .route("/metrics", axum::routing::get(metrics_handler))
        .route("/pubkey",  axum::routing::get(pubkey_handler))
        .with_state(AppState { registry, keys, metrics, cfg: cfg.clone() });

    let addr: SocketAddr = format!("0.0.0.0:{}", cfg.port).parse().unwrap();

    // SO_REUSEPORT: each Tokio worker thread gets its own accept queue
    // The kernel distributes connections across threads
    // This eliminates the accept() bottleneck at high connection rates
    let socket = Socket::new(Domain::IPV4, Type::STREAM, Some(Protocol::TCP)).unwrap();
    socket.set_reuse_port(true).unwrap();
    socket.set_reuse_address(true).unwrap();
    socket.set_nonblocking(true).unwrap();

    // TCP_NODELAY: disable Nagle's algorithm
    // WebSocket frames should be sent immediately, not buffered
    socket.set_nodelay(true).unwrap();

    socket.bind(&addr.into()).unwrap();
    socket.listen(65535).unwrap();  // large backlog for burst accepts

    let listener = tokio::net::TcpListener::from_std(socket.into()).unwrap();

    tracing::info!("Listening on {addr} with SO_REUSEPORT");

    // Graceful shutdown on SIGTERM/SIGINT
    let shutdown = async {
        tokio::signal::ctrl_c().await.ok();
    };

    axum::serve(listener, app)
        .with_graceful_shutdown(shutdown)
        .await
        .unwrap();
}
```

```rust
    pub fn from_pem(pem: &[u8]) -> Result<Self, GatewayError> {
        let key        = DecodingKey::from_rsa_pem(pem)?;
        let mut validation = Validation::new(Algorithm::RS256);
        validation.leeway  = 5;  // 5-second clock skew tolerance
        Ok(Self { key, validation })
    }

    pub fn verify(&self, token: &str) -> Result<Claims, GatewayError> {
        Ok(decode::<Claims>(token, &self.key, &self.validation)?.claims)
    }

    /// "*" matches everything
    /// Called on every subscribe command — must be fast
    #[inline]
    pub fn is_stream_allowed(allowed: &[String], stream: &str) -> bool {
        allowed.iter().any(|pat| {
            if pat == "*" { return true; }
            match pat.strip_suffix('*') {
                Some(prefix) => stream.starts_with(prefix),
                None         => pat == stream,
            }
        })
    }
}
```

```rust
// src/pubsub/nats.rs
pub async fn start(nats_url: &str, registry: Arc<Registry>, node_id: &str) {
    loop {  // outer loop: reconnect on NATS failure
        match run_consumer(nats_url, registry.clone(), node_id).await {
            Ok(_)  => break,
            Err(e) => {
                tracing::error!("NATS consumer error: {e} — reconnecting in 2s");
                tokio::time::sleep(Duration::from_secs(2)).await;
            }
        }
    }
}

async fn run_consumer(
    nats_url:  &str,
    registry:  Arc<Registry>,
    node_id:   &str,
) -> Result<(), GatewayError> {
    let client    = async_nats::connect(nats_url).await?;
    let js        = async_nats::jetstream::new(client);

    // Durable push consumer — one per gateway node
    // If gateway restarts, NATS replays unacknowledged messages
    let consumer  = js.get_stream("TURBOCABLE").await?
        .create_consumer(async_nats::jetstream::consumer::push::Config {
            durable_name:     Some(format!("gw_{node_id}")),
            deliver_subject:  format!("_TC_GW_{node_id}"),
            ack_policy:       AckPolicy::Explicit,
            max_ack_pending:  50_000,  // max unacknowledged messages in flight
            ..Default::default()
        }).await?;

    let mut msgs = consumer.messages().await?;

    while let Some(Ok(msg)) = msgs.next().await {
        // "TURBOCABLE.chat_room_42" → "chat_room_42"
        let stream = msg.subject
            .strip_prefix("TURBOCABLE.")
            .unwrap_or(msg.subject.as_str());

        let frame = Bytes::copy_from_slice(&msg.payload);

        // Fan-out is async but fast (ns per connection with try_send)
        registry.fanout(stream, frame).await;

        // Ack after fan-out — NATS won't redeliver
        msg.ack().await.ok();
    }

    Ok(())
}
```

# NATS JetStream Design and Wire Protocol

## 1. NATS Stream Configuration

```
Stream name:  TURBOCABLE
Subjects:     TURBOCABLE.>          ← matches any sub-subject
Storage:      File                  ← survives NATS restart
Retention:    LimitsPolicy
Max Age:      7 days                ← replay window
Max Bytes:    50 GB                 ← per-node storage cap
Max Msg Size: 1 MB                  ← reject oversized broadcasts
Replicas:     3                     ← survive 1 node failure
```

## 2. Subject Naming

```
TURBOCABLE.{stream_name}

Examples:
  TURBOCABLE.chat_room_42
  TURBOCABLE.user_99_notifications
  TURBOCABLE.global_announcements
```

The stream name in Rails code maps 1:1 to the NATS subject suffix.

## 3. KV Buckets

```
TC_PRESENCE
  Keys:    {stream}.{user_id}
  Values:  JSON { user_id, name, avatar, joined_at }
  TTL:     30 seconds (refreshed by heartbeat job)
  Storage: Memory (presence is ephemeral)

TC_PUBKEYS
  Keys:    rails_public_key
  Values:  PEM bytes
  TTL:     5 minutes
  Storage: Memory
  Gateways watch this key and hot-reload on change
```

## 4. Wire Protocol

**JSON mode** (ActionCable-compatible, default in dev):
```json
{ "command": "subscribe",   "identifier": "{\"channel\":\"ChatChannel\",\"room_id\":42}" }
{ "command": "unsubscribe", "identifier": "..." }
{ "command": "message",     "identifier": "...", "data": "..." }
```

**MessagePack binary mode** (production default):
```
[command:u8][identifier_len:u16][identifier:bytes][data_len:u32][data:bytes]

Commands:
  0x01  subscribe
  0x02  unsubscribe
  0x03  message
  0x04  ping
  0x05  pong
  0x06  confirm_subscription
  0x07  reject_subscription
  0x08  hello  (client announces last_seq for replay)
```

**Protocol negotiation** via WebSocket sub-protocol:
```
Sec-WebSocket-Protocol: actioncable-v1-json     → JSON mode
Sec-WebSocket-Protocol: turbocable-v1-msgpack   → binary mode (default)
```

## 5. Message Replay on Reconnect

```
Client sends on reconnect:
  { type: "hello", last_seq: "8841" }

Gateway:
  for each stream the client was subscribed to:
    js.get_stream("TURBOCABLE")
      .get_messages_by_subject("TURBOCABLE.{stream}", seq > 8841)
    → deliver each to client before resuming live feed

Client receives:
  { type: "message", seq: "8842", replayed: true, data: {...} }
  { type: "message", seq: "8843", replayed: true, data: {...} }
  ... (live messages follow)
```

# `turbocable` Ruby Gem — NATS Publisher

## What This Gem Does

One job: publish events to NATS from Ruby.
That is it. No WebSocket handling. No connection management.
The gateway does all of that.

```ruby
TurboCable.broadcast("chat_room_42", { message: "Hello" })
# → nats.publish("TURBOCABLE.chat_room_42", msgpack_bytes)
# → returns immediately (~microseconds)
```

## Why This Is Fast Enough

nats-pure is a pure Ruby NATS client that writes to a persistent
TCP connection. Publishing is:
1. MessagePack encode the payload (~1μs)
2. Write bytes to TCP socket (~5μs)
3. Return

At 1M users broadcasting 1 msg/sec into 10 chat rooms:
- That is 10 broadcasts/sec from Rails
- nats-pure can do 50k–100k publishes/sec
- You are using 0.01% of its capacity

The fan-out (1 event → 100k subscribers) is entirely in Rust.

## NATS Adapter

```ruby
# lib/turbocable/pubsub/nats_adapter.rb
# frozen_string_literal: true

require "nats/client"
require "msgpack"

module TurboCable
  module PubSub
    class NatsAdapter < Base
      SUBJECT_PREFIX = "TURBOCABLE"

      def initialize(servers:, stream_name: "TURBOCABLE", **)
        super()
        @stream_name = stream_name
        # Single persistent connection per Ruby process
        # nats-pure reconnects automatically on failure
        @nats = NATS.connect(servers)
        @js   = @nats.jetstream
        ensure_stream!
      end

      # @param stream [String]  e.g. "chat_room_42"
      # @param payload [Hash]
      # @return [void]  — returns in ~5μs
      def publish(stream, payload)
        encoded = MessagePack.pack(payload)
        @js.publish("#{SUBJECT_PREFIX}.#{stream}", encoded)
      rescue NATS::Error => e
        raise PublishError, "NATS publish failed: #{e.message}"
      end

      def connected? = @nats.connected?

      def shutdown
        @nats.drain
        @nats.close
      end

      private

      def ensure_stream!
        @js.add_stream(
          name:       @stream_name,
          subjects:   ["#{SUBJECT_PREFIX}.>"],
          storage:    :file,
          retention:  :limits,
          max_age:    7 * 24 * 3600,
          num_replicas: 3,
        )
      rescue NATS::JetStream::Error::StreamNameAlreadyInUse
        nil
      end
    end
  end
end
```

## What It Does

```typescript
// src/connection.ts
const BACKOFF_BASE = 500
const BACKOFF_MAX  = 30_000
const JITTER       = 0.3

export class Connection {
  private ws:           WebSocket | null = null
  private attempts:     number = 0
  private lastSeq:      string = "0"      // NATS sequence for replay
  private offlineQueue: Uint8Array[] = [] // messages queued while disconnected

  async connect(): Promise<void> {
    // Always fetch a fresh JWT — old one may have expired (60s TTL)
    const { token, gateway_url } = await this.fetchToken()
    const url  = `${gateway_url}?token=${token}`
    const proto = "turbocable-v1-msgpack"

    this.ws = new WebSocket(url, [proto])
    this.ws.binaryType = "arraybuffer"

    this.ws.onopen    = () => this.onOpen()
    this.ws.onmessage = (e) => this.onMessage(e.data as ArrayBuffer)
    this.ws.onclose   = () => this.scheduleReconnect()
    this.ws.onerror   = () => this.scheduleReconnect()
  }

  private onOpen(): void {
    this.attempts = 0
    // Tell gateway our last known sequence → triggers replay of missed messages
    this.send({ type: "hello", last_seq: this.lastSeq })
    // Drain offline queue
    for (const frame of this.offlineQueue) this.ws!.send(frame)
    this.offlineQueue = []
  }

  private onMessage(data: ArrayBuffer): void {
    const msg = decode(new Uint8Array(data))
    // Track sequence for replay on next reconnect
    if (typeof msg === "object" && msg !== null && "seq" in msg) {
      this.lastSeq = String((msg as Record<string, unknown>).seq)
    }
    this.emit("message", msg)
  }

  send(data: unknown): void {
    const frame = encode(data)
    if (this.ws?.readyState === WebSocket.OPEN) {
      this.ws.send(frame)
    } else {
      this.offlineQueue.push(frame)  // deliver on reconnect
    }
  }

  private scheduleReconnect(): void {
    const base  = Math.min(BACKOFF_BASE * 2 ** this.attempts, BACKOFF_MAX)
    const delay = Math.floor(base + base * JITTER * Math.random())
    this.attempts++
    setTimeout(() => void this.connect(), delay)
  }
}
```

```ruby
# lib/turbocable/server/installer.rb
# frozen_string_literal: true

module TurboCable
  module Server
    module Installer
      PLATFORM_MAP = {
        /x86_64.*linux/  => "linux-x86_64",
        /aarch64.*linux/ => "linux-aarch64",
        /arm64.*darwin/  => "darwin-arm64",
        /x86_64.*darwin/ => "darwin-x86_64",
      }.freeze

      def self.binary_path
        platform = RUBY_PLATFORM
        dir      = PLATFORM_MAP.find { |pat, _| pat.match?(platform) }&.last
        raise UnsupportedPlatformError, platform if dir.nil?

        path = File.expand_path("../../../../binaries/#{dir}/turbocable-gateway", __dir__)
        File.chmod(0o755, path) unless File.executable?(path)
        raise BinaryMissingError, path unless File.exist?(path)
        path
      end
    end

    UnsupportedPlatformError = Class.new(Error)
    BinaryMissingError       = Class.new(Error)
  end
end
```

```rust
async fn fanout_1000_subscribers() {
    let registry = Arc::new(Registry::new());
    let receivers: Vec<_> = (0..1000).map(|i| {

    // Slow client — buffer full (capacity 0 effectively)
```

# OSS Publishing

## Publishing Order (Always in This Order)
```
1. turbocable           (no deps on other TC gems)
2. turbocable-server    (depends on turbocable)
3. turbocable-rails     (depends on turbocable)
4. @turbocable/client   (independent npm package)
```

## RubyGems — Trusted Publishing (No Stored API Key)
```yaml
# In GitHub Actions:
- uses: rubygems/release-gem@v1
  with: { gem-name: turbocable }
```
Requires setting up OIDC trusted publisher on rubygems.org once.
`rubygems_mfa_required: "true"` in every gemspec — enforced at push time.

## npm — With Provenance
```bash
npm publish --provenance --access public
```
Links the npm package to the exact GitHub commit that built it via SBOM.

## Version Strategy
All three gems + npm package share one version number.
Single source of truth: `gems/turbocable/lib/turbocable/version.rb`

Before v1.0: minor versions may include breaking changes.
After v1.0: strict semver.

## GitHub Release = Binary Distribution
Every version tag triggers the release workflow which:
1. Builds 4 platform binaries (Linux x86_64, Linux ARM64, macOS ARM64, macOS x86_64)
2. Copies binaries into `turbocable-server` gem `binaries/` directory
3. Creates GitHub Release with binaries attached as assets
4. Publishes all gems + npm in the correct order
